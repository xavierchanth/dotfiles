# Address review feedback

Resolve the requested feedback with justified corrections and evidence.

1. [Inspect](../capabilities/inspect.md) published comments, review submissions and unresolved threads, including existing feedback.
2. [Assess](../capabilities/assess.md) each item against current code and intent. Distinguish warranted corrections, questions, already-addressed items and disagreements.
3. [Amend](../capabilities/amend.md) warranted changes within scope, then [verify](../capabilities/verify.md). Group coupled corrections and preserve traceability to feedback.
4. Use [GitHub actions](../capabilities/github-actions.md) for authorized responses or thread changes. Prepare suggested replies for the user when posting is not authorized. Resolve threads only when authorized and the concern is actually addressed.
5. Refresh feedback and checks after a push. Return revision and remaining state to a calling babysit workflow.

Completion means the selected feedback is addressed, or remaining decisions and blockers are explicit. A reviewer suggestion is evidence to evaluate, not automatic authorization to change design.
