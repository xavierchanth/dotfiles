# Web Applications

Map the immediate task and supporting capabilities to the working layout. Distinguish
global navigation, contextual actions, primary content, and supporting information
through placement and emphasis. Keep the user's current location and relevant state clear.

Choose density to support the work. Tables, lists, forms, canvases, and comparison views
have different spatial needs; let those needs determine the arrangement. Give repeated
data consistent alignment and make the important distinctions easy to scan.

Design representative loading, empty, populated, error, selection, and completion states
where relevant. Preserve orientation when content changes and make feedback visible
near the action or affected region. Include visible focus and accessible interaction cues.

Determine supported sizes from the actual product brief. Read
[screen adaptation](screen-adaptation.md) for layouts that span sizes. Reconsider how
working regions and dense information are presented as space contracts; preserve the
context required to complete the task. Inspect intermediate widths and realistic data.
