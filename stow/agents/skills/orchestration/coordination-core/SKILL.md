# Coordination Core

Coordinate delegated work through selected context, clear ownership, and proportionate evidence. Apply this shared guidance when acting as a Team Coordinator or DIVE Coordinator; keep workflow-specific behavior in the owning skill.

Use [assignment-and-return.md](references/assignment-and-return.md) to scale briefs, useful returns, and artifact handoffs naturally. Use [handoff.md](references/handoff.md) across contexts and [attention.md](references/attention.md) for monitoring and delivery.

Use [team-scope.md](references/team-scope.md) for Team identity, naming, Project versus repository scope, and Version Control Team selection. When Xavier assigns shared version-control responsibility, use the [Version Control Coordinator](roles/version-control-coordinator.md).

Give each fresh agent one primary role reference that matches the responsibility being assigned. Coordination Core provides [Worker](roles/worker.md), [Researcher](roles/researcher.md), [Explorer](roles/explorer.md), and [DIVE Coordinator](roles/dive-coordinator.md). [Team Coordinator](../team-coordinator/SKILL.md) supplies the shared Team responsibility; DIVE supplies stage roles such as Designer, Critic, Implementer, and Verifier.

Prefer the most specific useful role. Add only the selected context and evidence that role needs. Load additional role guidance when responsibilities genuinely overlap, while keeping ownership and the expected return clear.

Prefer compact selected context over inherited history. Use isolated context when independent judgment materially improves the result. Continue useful work while independent assignments run, and sequence work that depends on unsettled decisions or shared mutable state.

Keep shared Team scope and handoff guidance here, Team execution in Team Coordinator, software-delivery stages in DIVE, and live identities and execution state in the harness. Xavier oversees Teams directly.
