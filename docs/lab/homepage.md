# Homepage

Homepage is the rebuildable landing page for the personal lab pilot. The pinned
`v2.3.0` container runs on Hades and renders a small, declarative catalog of the
services Xavier can open.

## Product contract

- Runtime unit: `homepage.service`
- Loopback upstream: `http://127.0.0.1:3000`
- Readiness: unauthenticated `GET /api/healthcheck`, with HTTP 200 meaning ready
- Restart behavior: systemd restarts unexpected Podman container exits;
  stopping `homepage.service` removes the transient container
- Accepted ingress host: `lab.xavierchanth.xyz`
- Container image:
  `ghcr.io/gethomepage/homepage:v2.3.0@sha256:f820276654539cdc2cf0169f28188d135919a7984fad76d83d8d5ff1383f3705`

The product module owns the image pin, loopback listener, health behavior, and
dashboard content. Gateway Deploy owns the external origin, certificate,
tailnet listener, reverse proxy, and rollback of that route. The module does not
open firewall ports or define a Caddy route.

## Pilot configuration

The A0 dashboard contains links to Executor and the persistent ExcaliDash workspace. Its configuration is
generated by Nix and mounted read-only. It has no container socket, service API
tokens, widgets, or mutable application data. Homepage logs only to stdout.

Homepage's optional password/OIDC layer is disabled for this tailnet-only
pilot, so it needs no credential. `HOMEPAGE_ALLOWED_HOSTS` remains enabled and
accepts only the canonical tailnet-only hostname in addition to Homepage's
built-in loopback allowances. Authentication can be added later if the ingress
boundary expands beyond the tailnet.

## Validation

Before activation, evaluate the focused assertions and the Hades system. After
Gateway Deploy publishes the separate route, verify the local contract first:

```sh
curl --fail http://127.0.0.1:3000/api/healthcheck
sudo systemctl is-active homepage.service
```

Then verify the external origin from an approved tailnet client and confirm
that the dashboard link resolves to its separately owned complete origin.
